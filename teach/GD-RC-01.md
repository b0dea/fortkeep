# GD-RC-01 · No repo-poisoning indicators in the repos or editor extensions on this Mac

**Why:** The git scan hook (BL-RC-02) only sees what arrives after it's installed. Repos you cloned before, or copied in some other way, were never scanned, and they run the moment you start a dev server or open them in an editor or agent. A trojanized editor extension runs every time the editor starts.

**Real attack:** PolinRider, a North Korean campaign that also spreads through fake take-home interview projects, hides a loader after more than a hundred spaces at the end of files such as `postcss.config.mjs` or `tailwind.config.js`, ships a "font" that is really JavaScript, or adds a `.vscode/tasks.json` that runs when the folder opens. Its spreader rewrites commits while keeping the original author name and date, and related North Korean repos add git hooks that download more code ([source](https://github.com/OpenSourceMalware/PolinRider), [source](https://github.com/OpenSourceMalware/PolinRider/issues/9), [source](https://opensourcemalware.com/blog/lazarus-group-uses-git-hooks-to-hide-malware)).

**Check it yourself:** in a repo, `git ls-files | grep -E 'config\.(js|mjs|ts)$' | xargs grep -nE '[;})] {40,}[^ ]'` finds code hidden after a long run of spaces.

**How to fix:** a finding is serious until shown otherwise. Don't install, build, run or open that repo in an agent or an editor with automatic tasks; type `/if-red` and follow it. "Lower-confidence" findings in the note (a task that runs when the folder opens, a package registry that isn't a public one, agent instructions that start a setup script) don't fail the check, but look at each one before you next use that repo.

**What the agent is doing:** finding the git repos in your code folders (`~/dev`, `~/Developer`, `~/code`, `~/src`, `~/Projects`, `~/work`, `~/git`, `~/repos`, `~/Documents/GitHub`) and in `~/Desktop` and `~/Downloads`, where cloned or unzipped repos often land, four levels deep, and reading their tracked files, installed git hooks, the hooks their own git config sets and commit history with the same rules as the git scan hook. It also reads the VS Code, Cursor and Windsurf extension folders for the loader's markers. Hidden folders and private folders are skipped, inside a repo too; a folder macOS privacy settings hide, or a hook or history it can't read, is named and the check gives ERROR. Nothing in those repos is run. The sweep takes a while, so it runs in the weekly security check (BL-AU-02); other reviews show that sweep's result and its age, and fail when it is more than 8 days old. A repo with more than 5000 files has only its config, hook and agent files read, and the note names it.
